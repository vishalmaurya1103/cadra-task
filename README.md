# Larkfield Customer Care agent service

An HTTP service that reads a support email and returns the desk's decision. It proposes
actions only: it never refunds, sends mail or changes data. See `NOTES.md` for the locked
policy decisions and `APPROACH.md` / `ARTEFACT.md` for the written deliverables.

## Requirements

- Python 3.11 or newer
- The data-room folder already present in this repository
  (`*/data/customers.csv`). `src.prepare_data` finds it automatically.

## Quick start (local)

Run these from the repository root.

```bash
# 1. Create and activate a virtual environment
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# 2. Install dependencies
python -m pip install --upgrade pip
pip install -r requirements.txt

# 3. Optional: local configuration (the service also runs without an LLM key)
cp .env.example .env
# edit .env and set LLM_API_KEY, or leave it empty for deterministic local runs

# 4. Build the read-only data index (source CSVs are never modified)
python -m src.prepare_data

# 5. Start the API
uvicorn src.main:app --reload --host 127.0.0.1 --port 8000
```

Open <http://127.0.0.1:8000/health>; it must return:

```json
{"status":"ok"}
```

Alternative start command (uses `PORT`, default `8000`; no auto-reload):

```bash
python -m src.solution
```

### Local configuration (`.env`)

`.env` is gitignored; `.env.example` is the template.

| Variable | Purpose | Default |
|---|---|---|
| `LLM_API_KEY` | OpenAI-compatible API key. If empty, the service uses deterministic regex extraction. | empty |
| `LLM_BASE_URL` | Provider base URL | `https://api.openai.com/v1` |
| `LLM_MODEL` | Model name used for extraction and cost lookup | `gpt-4o-mini` |
| `PORT` | Port for `python -m src.solution` | `8000` |
| `DATA_DIR` | Data-room folder if auto-detection fails | auto-detected |

Never commit `.env`. Set the same values as environment variables on your host.

## Try the API locally

Health:

```bash
curl -s http://127.0.0.1:8000/health
```

Create a ticket (this one returns `PROCEED` with a `$129.00` refund proposal):

```bash
curl -s -X POST http://127.0.0.1:8000/tickets \
  -H 'Content-Type: application/json' \
  -d '{
    "ticket_id": "DEMO-1",
    "received_at": "2026-10-01T10:00:00+00:00",
    "channel": "email",
    "from": "ben.tanaka1@mail.example",
    "to": "support@larkfield.example",
    "subject": "Damaged Arc floor lamp",
    "body": "My Arc floor lamp from order LF-100201 arrived damaged (photo attached). Please refund me.",
    "attachments": [
      {"file_name": "photo.jpg", "content_type": "image/jpeg", "content_base64": ""}
    ]
  }'
```

Read a run (use the `run_id` returned above):

```bash
curl -s http://127.0.0.1:8000/runs/<run_id>
```

Decision for a run that is waiting for a person:

```bash
curl -s -X POST http://127.0.0.1:8000/runs/<run_id>/decision \
  -H 'Content-Type: application/json' \
  -d '{"decision":"approve","approver":"lead@larkfield"}'
```

Ledger:

```bash
curl -s http://127.0.0.1:8000/ledger
```

A ticket that needs approval (returns `PEND`, `$185.00`, Support Lead):

```bash
curl -s -X POST http://127.0.0.1:8000/tickets \
  -H 'Content-Type: application/json' \
  -d '{
    "ticket_id": "DEMO-PEND",
    "received_at": "2026-10-02T11:00:00+00:00",
    "channel": "email",
    "from": "carla.ivanova2@mail.example",
    "to": "support@larkfield.example",
```

## Reset local state

Runs, decisions and the ledger live in `build/state.sqlite`. Delete it to start clean:

```bash
rm -f build/state.sqlite
```

`build/data_index.json` and `build/data_report.json` are regenerated by
`python -m src.prepare_data`; `build/` is gitignored.

```bash
pytest -q
python -m eval.run
```

- `tests/test_regressions.py` covers ledger-based duplicate suppression (original + `Fwd:`
  copy + `>`-quoted copy = one refund) and the late-status-question `PROCEED` path,
  including a deliberately misleading LLM response.
- Scored eval: 15 labelled tickets + 13 new negative cases (`eval/new_negative_cases.json`).
- Pass rule: `outcome`, `human_approval_required`, `approver_role` exact; proposed amount
  within $0.01 when expected; `reason_codes` a superset of expected; `resolved_order_ids`

- Public tickets (`inbox/public_tickets.json`) are smoke-checked only, never in the pass rate.
- Eval is deterministic and offline by default. Use `--use-llm` to exercise the configured

## Endpoints

- `GET /health` -> `{"status":"ok"}`
- `POST /tickets` -> run for one ticket
- `GET /runs/{run_id}` -> current run, including one waiting for a person
- `POST /runs/{run_id}/decision` -> `{"decision":"approve"|"reject","approver":"..."}`
- `GET /ledger` -> recorded proposals (`REFUND`, `REPLY`, `ESCALATION`)

Duplicate detection is ledger-based, not email-text-based: if an order line already has a
`REFUND` that is `PROPOSED` or `APPROVED`, a new request for that line gets its own `run_id`
plus `duplicate_of` and creates no second ledger action. Decisions are idempotent: the first
decision updates the proposal once; later decisions return the same run.

## Added run fields (allowed by the contract)

- `amount_usd`: proposed refund amount, null when not a refund.
- `run_status`: `PENDING_APPROVAL`, `COMPLETE`, `APPROVED` or `REJECTED`.
- `resolved_orders`: every referenced order with `matched` true/false (multi-order emails).
- `duplicate_of`: `run_id` that already holds a `PROPOSED`/`APPROVED` `REFUND` for the
  same order line, otherwise null.
- `decision`: `{decision, approver, decided_at}` after a person decides, otherwise null.
- `latency_ms`: server-side processing latency.
- `trace.llm_used` / `trace.llm_error`: whether the optional extraction model succeeded.

## Model and cost

One OpenAI-compatible extraction call per ticket when `LLM_API_KEY` is set. The deterministic
policy engine decides; the model only helps parse the email. Policy signals (injection,
defect, refund/return intent, shipping, order IDs, ticket type) are regex-driven and are
never overridden by the model. If the call fails, regex extraction is used and the run
records 0 tokens plus the error. Cost is computed from a per-model OpenAI list-price table in
`src/trace.py` using the response's token counts.

## Deploy (Render)

- Build command: `pip install -r requirements.txt`
- Start command: `uvicorn src.main:app --host 0.0.0.0 --port $PORT`
- Health check path: `/health`
- Set `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` in the Render dashboard (never in git).

## Layout

- `src/prepare_data.py`, `src/data.py` - read-only normalization/index and data report
- `src/extract.py` - order/email normalization, intent and product extraction, optional LLM
- `src/policy.py` - RP-3.2 evaluator and checks/evidence
- `src/reply.py` - decision-consistent reply templates
- `src/trace.py` - model calls, token counts and price-table cost
- `src/store.py` - SQLite runs/ledger/decisions and active-refund lookup
- `src/service.py` - orchestration, active-refund suppression and decisions
- `src/main.py` - FastAPI endpoints
- `eval/` - cases, runner and timestamped results
- `tests/` - pytest regressions
